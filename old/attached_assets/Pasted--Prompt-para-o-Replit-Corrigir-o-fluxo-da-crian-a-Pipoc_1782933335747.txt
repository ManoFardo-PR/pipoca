## ⚠️ INTENÇÃO AUTORAL — NÃO DERIVAR

Este é o coração do produto. Se você se pegar simplificando para qualquer coisa abaixo, **pare e releia**.

A mecânica é **composição autoral**, não sequência de painéis:

- A criança **combina múltiplos objetos** numa cena; **a história nasce do arranjo dela**.
- **A história É a recompensa.** Ler não ganha um prêmio separado — ler faz a *própria história crescer*. O vaga-lume (moeda) é testemunha do esforço, não suborno.
- Cada leitura no portão **destrava uma nova rodada** com **mais de uma opção de objeto** para escolher. A escolha entre opções é o que faz cada partida divergir.
- O resultado de cada partida é **um conto coeso e diferente**, segurado por **âncoras travadas** (início e fim).

**NÃO é, em hipótese alguma:**

- ❌ uma esteira de "próximo → próximo → próximo" (um objeto de cada vez, sem escolha real);
- ❌ organizar/ordenar uma tira de figuras e depois ler tudo de uma vez;
- ❌ um monte de frases desconexas — cada objeto é uma **micro-cena tolerante a vizinho** que lê bem em qualquer ordem;
- ❌ recompensa por compliance (estrelinha/pontos por obedecer).

Se a sua implementação deixar a criança só apertando "próximo", ela está errada.

## 📐 O modelo v2, preciso

Conjunto **fechado de 7 objetos** por cenário. 4 rodadas:

| Rodada | Revela | Escolhe | Posição |
|---|---|---|---|
| 1 | 4 objetos | escolhe e **ORDENA 3** | 3 slots livres; ao confirmar, **as pontas (1º e último) TRAVAM** |
| 2 | +1 objeto | escolhe 1 | insere **só no miolo** (entre as pontas) |
| 3 | +1 objeto | escolhe 1 | insere **só no miolo** |
| 4 | +1 objeto | escolhe 1 | insere **só no miolo** |

Regras:

- **Banco = novas + sobras**: objetos revelados e não escolhidos continuam disponíveis nas rodadas seguintes (nenhum objeto se repete).
- **Moldura fixa**: toda história = `abertura` + as `contas` dos objetos **na ordem da linha** + `desfecho`. Abertura e desfecho são autorados e sempre iguais; só o miolo varia.
- **Temperos são SABOR, não portão**: uma regra `tem:X` enriquece a frase quando dois objetos coexistem — **nunca bloqueia** uma escolha.
- **Níveis n1–n4** = dificuldade de leitura por perfil da criança (não são as rodadas). Renderize o nível do `perfil.nivel`.
- **Portão perdoador**: leitura imperfeita → dica calorosa e nova tentativa. **Nunca X vermelho, nunca punição.**

Conteúdo já pronto e validado em `docs/quintal.v2.json` (esquema `pipoca.grafo-autoral.v2`): campos `moldura {abertura, desfecho{convergente, aberto[]}}`, `rodadas[]`, `objetos{ id: {conta{n1..n4}, tempera[], ...} }`.

## 🔧 Trabalho técnico

### 1. Criar `src/core/composicao.ts` (o motor v2)

Função pura que consome o grafo `quintal.v2.json`. Contrato exato (respeite os nomes — o `index.html` já os chama):

```ts
type EstadoComp = {
  cenarioId: string;
  rodada: number;          // 1..4
  banco: string[];         // ids disponíveis p/ escolher (novas + sobras)
  linha: string[];         // ids colocados, EM ORDEM
  pontasTravadas: boolean;
  historiaTexto: string;
};

iniciar(cenario, modos): EstadoComp           // rodada 1, banco = revela da R1, linha vazia
bancoDaRodada(estado): string[]               // revela da rodada atual + sobras
podeInserir(estado, objetoId, slotIndex): boolean  // R>=2: só miolo (0 < slot < len); pontas travadas
inserir(estado, objetoId, slotIndex): EstadoComp
ordenarR1(estado, ordemIds: string[]): EstadoComp   // coloca/ordena os 3; trava pontas
montar(estado, nivel): string                 // abertura + contas(na ordem, aplicando tempera) + desfecho(se convergiu)
abrirProximaRodada(estado): EstadoComp         // rodada++, atualiza banco
convergiu(estado): boolean                     // true quando a rodada 4 foi lida
```

`montar` tece: `abertura[nivel]` + para cada id em `linha` a `conta[nivel]` (ou a variação de `tempera` se a condição `tem:` estiver satisfeita pela linha) + se `convergiu`, `desfecho.convergente[nivel]` (ou `aberto` conforme último objeto, se `modos.desfecho === 'aberto'`).

### 2. Expor no bridge

Em `src/app/bridge.ts`, adicionar `window.PipocaCanonico.composicao = { iniciar, bancoDaRodada, podeInserir, inserir, ordenarR1, montar, abrirProximaRodada, convergiu }`. Depois **rebuildar o bundle**:

```
bun build src/app/bridge.ts --target=browser --outfile=pipoca.bundle.js
```

### 3. Religar o fluxo da criança no `index.html`

Substituir a mecânica v1 (`tiraStrip`, `_dragId`, `heroVariant`) pelo estado `state.comp` e os handlers `_t3EscolherCenario → _t4Colocar → _t4Confirmar → _t5Confirmar`, chamando `PipocaCanonico.composicao.*`. Use `docs/index.v2.scaffold.html` como referência de estrutura (os call-sites e a sequência já estão desenhados lá).

Sequência: T3 escolhe cenário → `iniciar` → T4 Palco (R1 ordena 3 / R2–4 insere no miolo) → `montar` → T5 portão lê → sucesso credita + `abrirProximaRodada` → `convergiu` ? T7 Pote : volta ao T4.

## 🏁 Critério de pronto (linha verde do Pietro)

1. Na R1, a criança **escolhe e ordena 3** de 4 objetos revelados; as pontas travam.
2. Lê a história no portão; ao ler, **destrava a R2**; insere **1 no miolo**; repete até a R4.
3. A história tecida a partir do `quintal.v2.json` lê **coerente em qualquer ordem** de composição, no nível do perfil.
4. Na R4, converge para o desfecho e vai ao Pote.
5. `bun build` passa; o app carrega sem erro de console; a linha verde roda de ponta a ponta.
